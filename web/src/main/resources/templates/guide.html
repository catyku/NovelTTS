五分鐘做出你的第一本有聲書

把小說純文字丟進去，AI 會自動切章、判斷每句話是旁白還是角色說話、 挑選音色，再逐段合成語音。你會拿到每段音檔、每章合併檔，和整本的下載 ZIP。

不需要註冊，也不需要登入。 你的小說、角色與音檔全部存在這台電腦的瀏覽器裡，伺服器只做無狀態的 AI 運算， 不保存你的任何資料。唯一需要你自己準備的是一把 OpenRouter API Key。

1準備一把 Key

到 OpenRouter 註冊並建立 API Key，貼到「設定」頁。這把 Key 只存在你的瀏覽器裡。

2匯入小說

貼上內文或選文字檔。系統會依「第X章」標題自動切章，沒有標題就按字數切。

3分析與合成

按「觸發 AI 分析」辨識角色，再按「觸發語音合成」產生音檔。全程在你的瀏覽器。

4下載成品

合併本章、合併整本，或直接下載 ZIP（內含段落檔、章節檔與整本檔）。

✎用 AI 產生小說

不想自己打字？到「AI 生成」頁，寫下你的想法， 設定章節數與每章的字數範圍，AI 就會逐章把故事寫出來。 寫完可以直接下載 TXT，或匯入成小說接著做語音合成。

三個可選的步驟

  1. 產生大綱（可跳過）—— 先讓 AI 列出每章的標題與走向， 之後每一章都會帶著這份大綱生成，全書方向比較不會跑掉。
  2. 開始生成 —— 逐章呼叫 AI。每章都會把上一章的結尾帶進去， 所以劇情是連貫的，不會每章像各寫各的。
  3. 取用成果 —— 下載 TXT，或按「匯入為小說並前往語音合成」。
中途中斷也不會白費。 每生成完一章就會存進瀏覽器，所以就算你按了「停止」， 已完成的章節仍然保留在歷史記錄裡，可以繼續下載或匯入。
關於花費。 每章都是一次 AI 呼叫，章數越多費用越高。 建議先試 2–3 章確認方向，滿意後再往下生成。 生成歷史只存在你的瀏覽器裡，伺服器不會保存任何生成內容。

1設定你的 OpenRouter API Key

分析與語音合成都由 OpenRouter 的模型完成，所以需要一把它的 API Key。 到 openrouter.ai 註冊後，在 Keys 頁建立一把 Key（需要先在額度頁加值或綁定付款方式）。

取得 Key 後打開設定頁，貼進「你的 API Key」欄位，按「儲存 API Key」。 想確認能不能用，可以直接按旁邊的「測試連線」。

Key 會跑到哪裡？ 儲存在瀏覽器的 localStorage，只在呼叫閘道時放在 HTTP 標頭 X-OpenRouter-Key 裡送出。伺服器只在「那一次請求」的記憶體中用它， 不寫入資料庫、不存檔、不記錄到 log。
不想每次都貼？ 同一台電腦的同一個瀏覽器會記住你的 Key。換電腦或清除瀏覽器資料就要重新貼一次。

設定頁下方還有「全站預設值」—— 這是系統提供的音色庫與模型建議值， 按「設為旁白」「設為預設」或「套用」就能套進你自己的設定。套用後存進你的瀏覽器，不影響其他人。

2匯入小說

到小說頁，在「新增小說」區塊填入標題、作者與內文。 內文可以直接貼上，或按「從文字檔匯入」選一個 .txt。

切章規則

系統會自動辨識章節標題來切分：

類型範例
中文章節第一章、第 12 回、第三节
英文章節Chapter 1、CHAPTER IV
Markdown 標題## 第一章
沒有標題依字數上限自動切（預設 3000 字，可在設定頁調整）
章節標題不會被念出來。 標題只存在章節名稱裡，不會混進內容變成旁白 —— 你不會聽到「第一章 夜歸」被唸一遍。

按「建立」後，系統會立刻切好章節並顯示在列表中。 所屬群組與集數順序先留空沒關係， 稍後想讓多集共用音色再回來指定（見步驟 6）。

3觸發 AI 分析

進入小說詳情頁，按「觸發 AI 分析」。 系統會逐章送去分析，判斷每一段是旁白（NARRATION）還是某個角色在說話 （DIALOGUE），並抽出情緒與語氣。

分析結果會建立角色清單。你可以到「角色音色」頁微調，詳見步驟 5。

原文會被保留嗎？ 會。AI 只做「判定這句是誰說的、有什麼情緒」，不會摘要或改寫你的文字， 最多補上標點、拿掉對話引號。實際送去合成的就是原文。

4觸發語音合成

按「觸發語音合成」。系統會把相鄰的段落依說話者打包成 multi-speaker 請求，一次送出多個 turn —— 這比逐段呼叫快得多，音色切換也順。

音檔會存進你的瀏覽器（IndexedDB），所以重新整理頁面不會消失。 段落音檔顯示的「音色」欄就是這段實際用的 voice ID —— 可以拿它對照角色設定。

合成要花多少時間？ 大約每 10 秒文字需要 2–4 秒合成（視模型而定）。長篇小說建議分章進行， 系統會顯示「合成第 X/Y 章」的進度。

5調整角色音色

在小說詳情頁按「角色音色」進入。AI 會依角色在文中的出現頻率自動挑選音色， 你可以隨時改。手動改完記得按該列的「儲存」。

語氣指令怎麼寫

語氣指令是給 TTS 模型的具體指示，越具體越好。實測有效寫法：

想要的感覺指令範例
沉穩敘事語氣沉穩，敘述節奏平緩
清冷疏離語氣清冷，語速偏慢
低沉話少語氣低沉，話少，帶點冷幽默
語氣指令不是裝飾。 實測（同一個 voice ID，量測音量與時長的變異率）： 沒有 instructions 時音量變異 9.3%、時長變異 6.2%； 有 instructions 時音量變異降到 1.2%、時長變異 4.7% —— 約 3.5 倍的穩定度改善。 這是跨集音色一致性的關鍵。

頁面上方還有「自動指派音色」按鈕，會把語氣出現最多的角色依序配給不同的音色， 適合還沒決定要分配誰的時候。

6用群組讓音色跨集一致

同一本連載小說常常分好幾十集慢慢出版。如果每一集單獨分析，同一個角色會拿到不同音色， 聽起來像換了配音員。群組就是為了解決這件事。

  1. 到群組頁建立群組（例如「燈火重亮」）。
  2. 展開群組，設定旁白音色與旁白語氣（跨集共用）。
  3. 在「共用角色」新增每一位角色：名稱、別名、音色、語氣。
  4. 回到小說頁，把每一集匯入時的「所屬群組」指到這個群組。

實測結果

兩集各自獨立分析，群組的共用角色自動套用：

集數角色套用音色套用語氣
第一集林晚Aoede語氣清冷，語速偏慢
第一集陳硯Charon語氣低沉，話少，帶點冷幽默
第二集林晚Aoede語氣清冷，語速偏慢
第二集陳硯Charon語氣低沉，話少，帶點冷幽默

注意「套用音色」欄：第二集的 AI 是獨立分析的，卻自動對上了群組裡的設定， 連語氣指令都一樣。

7合併與下載

合成完之後有三種取得成品的方式：

動作在哪裡產出
合併本章段落與音檔頁把本章所有段落音檔接成一個 MP3
合併整本小說詳情頁把所有章節音檔接成整本 MP3
下載 ZIP小說詳情頁內含段落檔、章節檔與整本檔
合併與打包在哪裡做？ 在伺服器端（需要 ffmpeg 做音檔合併），但同樣是無狀態的： 伺服器收位元組、合併、回傳，不留任何檔案。 這樣你的瀏覽器不用載入 30MB 的 ffmpeg.wasm。

8資料存在哪、如何備份

這個系統的資料分布是這樣的：

資料放在哪
小說內文、章節、角色、段落你的瀏覽器 IndexedDB
音檔（MP3）你的瀏覽器 IndexedDB
群組設定、音色指派你的瀏覽器 IndexedDB
OpenRouter API Key你的瀏覽器 localStorage
伺服器不保存你的任何資料
伺服器（共用）音色庫、模型清單、模型定價 —— 建議值而已

備份

到設定頁最下方按「匯出我的資料」，會下載一個 JSON 檔， 內含你的小說、角色、群組與設定（不含音檔，也不含 API Key）。

清除瀏覽器資料 = 作品消失。 因為資料只存在你的電腦上，無痕模式或清除網站資料都會刪掉它。 重要的作品請記得用「匯出我的資料」備份。

容量限制

瀏覽器給網站儲存空間通常是數百 MB 到數 GB。一本長篇小說加上全部音檔 （一小時音頻約 50MB）可能就會逼近上限。音檔過多時，建議合成完就下載 ZIP， 再從設定頁清除資料。

?常見問題

為什麼不用註冊就能用？

因為伺服器不需要記住你是誰。你的資料全在瀏覽器，伺服器只是個「AI 運算閘道」—— 收到請求、呼叫 OpenRouter、回傳結果，連你的 Key 都不保存。 這樣一來伺服器端沒有你的資料可漏，公開服務的隱私風險也就低很多。

那我登入帳號有什麼用？

帳號模式是選用功能，目前能讓你把作品存到伺服器資料庫（跨裝置）。 但要提醒：訪客模式的資料不會自動同步到帳號，兩邊目前是各自獨立的。 登入後看到的是另一套（較舊的）介面。

換電腦怎麼辦？

訪客模式的資料跟著瀏覽器走，換電腦就沒了。兩種做法： 在舊電腦用「匯出我的資料」備份 JSON（不含音檔），或登入帳號模式存到伺服器。

音檔聽起來怪怪的／語速不對？

優先調整角色的「語氣指令」—— 那是影響最大的因素。 其次檢查「全域語氣」（設定頁），它會套用到所有沒特別指定角色的段落。 也可以在段落頁個別重跑某一段。

某個角色被念成別人的聲音？

這通常表示兩個角色被配到同一個音色。到角色頁用「自動指派音色」讓它們分開， 或手動指定不同音色後按「儲存」，再重跑受影響的段落。

會不會把我的內容送到第三方？

會，這是這類工具的本質：分析與合成的內容必然要送到 OpenRouter 的模型才能運算。 差別在於伺服器不保留 —— 請求處理完就結束，沒有資料庫紀錄、沒有 log。 但 OpenRouter 那端的處理則不在本系統的控制範圍內。

分析失敗或合成失敗怎麼辦？

先按「測試連線」確認 Key 有效、額度充足。Key 無效會明確提示 「OpenRouter API Key 無效或尚未設定」。額度用盡會回 429。 其他狀況請看該頁的紅色錯誤訊息。

可以呼叫一次處理很長的小說嗎？

可以，但會分章送出。若單一章節很長（沒有章節標題時），可以在設定頁把 「章節字數上限」調小，讓切分更細、進度更明顯。

還是卡住？ 系統的公開 API 是無狀態的，可以直接用 curl 呼叫： POST /api/gateway/analyze（帶 X-OpenRouter-Key 標頭）。 詳細格式見 README 的「對外 API：無狀態 AI 閘道」章節。
